# Phase 5 月结、结算单与主动提醒

## 交付范围

Phase 5 提供版本化月结周期、自动和手动月结批次、进度与失败重试、财务审核、结清、
等级建议人工复核、Word/PDF/ZIP 结算单，以及面向内部员工的主动提醒中心、浅规则、
模板、生命周期日志和可配置钉钉通知。

完整订单 CRUD、多维查询、看板、复杂规则表达式和面向客户的消息发送不在本阶段。

## 月结运行关系与历史数据闭环

月结批次使用 `settlement_run_members` 记录每个 eligible agent 的处理结果。
`SettlementRun` 仍表示一次执行批次，`Settlement` 仍表示月结业务事实；
`settlement_run_id` 只表示生成来源，`import_batch_id` 只表示历史导入来源。
因此，后续运行发现历史月结时，成员结果为 `existing`，但不会修改历史月结的
生成来源。批次统计、周期金额和失败详情从成员关系重新聚合，旧 JSON 字段只在
兼容期作为投影维护。

历史导入在月明细、`OrderCommission` 和月结汇总提交后，只有在明细金额与汇总
完全一致时才建立 `SettlementItem`；明细金额始终读取已有的
`OrderCommission` 快照，不重新解析历史费率。已被批次成员引用的历史月结会
阻止导入回滚，并返回业务级提示。

## 月结规则

- PR6 起新配置的统计周期固定为自然月，默认每月 10 日 09:00、`Asia/Shanghai`
  生成上一个自然月；Scheduler 仍每分钟检查，生成日及时间到达后才生成，停机后在
  当月恢复时补偿生成且保持同周期幂等。配置修改从下一次生成边界生效。
- `settlement_configurations.generation_day` 是新配置的版本化生成日，默认值为 10；
  旧配置的 `generation_day` 为空，继续使用 `boundary_day` 重建历史周期。不得把
  `boundary_day` 改写为 10 来模拟 PR6，也不得重解释已有 Run 的周期。
- 按周期内合作起止日期与周期相交的代理商参与，不使用代理商当前合作状态判断历史范围；按周期内已完成订单的推广费快照汇总。月结不会重新解析费率，
  缺少推广费或周期冲突会使对应代理商任务明确失败。
- 新月结状态为待审核、驳回、已通过和已结清；历史导入的已对账、已结清状态保留。
- 月结中心支持选择最近已关闭的往期周期生成月结；往期生成复用现有批次、代理商快照、审核、文档和结清流程，同一周期已有批次时保持幂等，不重复覆盖。往期节点按相邻配置边界重建，保留真实的配置切换过渡周期。
- 审核使用正数 KRW/CNY 汇率计算人民币分值，Word 和 PDF 来自同一内容快照并保存于
  私有磁盘。
- 待审核或驳回月结详情会从接口盒子 KRW/CNY 报价服务预填六位小数汇率；该服务每日更新，
  报价来源、时间、可用状态和人工覆盖标记随月结保存。成功报价缓存十分钟，报价失败会明确提示，审核人仍可人工输入正数汇率。
- 仅超级管理员可在“待审核”“已审核”和“已结清”之间更正当前月结状态，且必须填写原因；回退到待审核会在同一事务中撤销结算明细、删除失效文档和等级建议、清空汇总金额，但保留此前采用的结算汇率，再以更正前后值、原因和 IP 记录审计。月结使用独立生成状态，允许已明确生成但明细数为零的正常月结进入审核；回退后必须重新生成。汇率支持手动获取最新报价，报价失败时区分“无旧值”和“保留旧值”，并记录最近尝试时间。历史导入的 `paid`、`reconciled` 状态不允许更正。
- 月结中心批次按 `agent_id`、`id` 预加载并稳定排序，页面只保留一个批次轮询容器；每个批次可独立折叠，
  折叠状态在 Livewire 轮询时保留。月结详情支持在同一 `settlement_run_id` 内按相同排序上一条/下一条连续审核，
  没有批次关联的历史记录不显示邻接导航；月结中心另外展示这些未关联批次的历史月结记录。
- PR7 起月结中心默认展示最新已生成周期，并可从已生成周期下拉切换当前展示批次；历史归档使用业务日期起止筛选，
  采用 `period_start <= businessTo AND period_end >= businessFrom` 的周期重叠语义，不使用生成、创建或审核时间。
  从批次展开的代理商行可直接下载对应的 Word/PDF 文档；没有文档但状态允许时可在代理商行按需生成。进入代理商详情时保留当前展示周期，返回月结中心后仍恢复该周期。
  已结清月结重新进入详情时，审核阶段生成的 Word/PDF 文档仍可下载；历史导入的 `paid`/`reconciled` 月结也可在月结中心代理商行或只读详情中按需生成并下载相同格式的明细文档，且不改变历史状态或 `generation_status`。
- 月结批次启动前会预检周期内已有的月结记录。已有记录不覆盖、不派发生成任务，并在批次中计入
  `existing_agents`；只有尚无记录的代理商才进入生成队列。批次完成数为新生成、已有记录和失败数之和，
  仅存在真实生成异常时才进入部分失败状态。
- 批次存在失败项时，月结中心提供当前失败项详情页、全部失败项重试和私有 XLSX 报告下载。
  失败页只读取 `settlement_runs.errors` 当前未解决内容，不新增失败历史表；报告下载完成后删除临时文件。
  业务校验异常可展示，非预期异常仅记录日志并以参考编号反馈，不泄露 SQL、服务器路径或完整堆栈。
- 月结失败项以稳定消息键和命名参数写入 JSON；页面和 XLSX 在读取时按当前 Locale 渲染。已知历史中文失败原因会映射到对应消息键，无法识别的历史自由文本降级为安全说明；新发生的非预期异常只显示带参考编号的安全说明。汇率报价失败同样保存消息键与参数，旧 `exchange_rate_quote_error` 字段继续保留以支持旧镜像回退。
- 等级建议以月推广费总额匹配同一政策体系门槛，只有超级管理员人工批准后才安排
  下月生效。

## 主动提醒规则

- 内置预约前 3 天、前一天、当天及术后 1/7/30/90/180 天提醒；前一天和当天任务的建议
  明确要求客服联系客户确认到店安排。
- 浅规则支持状态变化、白名单日期字段偏移、固定周期、指定节假日日期和手动触发；
  指定节假日规则复用 `trigger_config` 中的 `date`/`time`，多日节假日配置多条规则，
  不新增节假日表。适用范围一次只选全部客户、代理商、项目、负责人或合作状态之一。
- 提醒使用稳定去重键。改期重排未完成任务，预约取消关闭相关任务；模板修改不改写
  已生成实例。指定节假日规则使用 `holiday-rule:{ruleId}:{customerId}:{date}` 去重，
  重复扫描、跨日扫描和停用规则不会产生重复或错误任务。
- 内置模板使用稳定 `system_key`，名称、标题和建议在读取时按当前 Locale 投影；管理员自定义内容保持原文。系统生成提醒把消息键与参数写入 `localized_content`，因此同一条历史提醒可随查看者语言渲染，旧标题和建议列仍保留以支持旧镜像回退。
- 普通内部用户只能查看分配给自己或自己创建的提醒；超级管理员可查看全部任务、
  完成率、规则与全局模板。
- 提醒只面向内部员工。钉钉未启用时站内提醒继续运行并显示未启用状态；发送失败记录
  日志并可由队列重试。

## 数据所有权

- Settlement 拥有月结配置、运行批次、结算单、结算明细、文档和等级建议。
- Reminder 拥有规则、模板、提醒实例与执行日志。
- Agent 拥有代理商资格、等级上下文与等级生效历史；Order 拥有订单和预约；Customer
  拥有提醒候选客户数据。跨模块协作只通过 Application Contract/Data。

事务与异步失败语义见
[ADR-0007](../adr/0007-phase-five-settlement-reminder-processing.md)。
