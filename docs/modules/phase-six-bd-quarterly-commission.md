# PR6 BD季度提成

## 当前业务口径

PR6 当前实现采用明确、可替换的第一版默认口径：订单 `amount_krw` 作为提成基数，币种为
KRW，使用基点费率并按半入取整计算。规划文档中列出的业绩基数、币种、基础费率、分档方式、
人工调整权限和确认后更正归属仍属于产品确认项；系统不会用一次修改覆盖历史规则，而是新增
`bd_commission_rules` 生效日期版本。未配置生效规则时，季度正式生成会以明确错误阻止。

## 事实与生命周期

- 订单按 `occurred_on` 进入自然季度边界，季度末包含在本季度内。
- 订单完成或更正时写入 `business_attribution_snapshot`，其中保存发生日期对应的代理商业务组和
  BD 成员快照；季度生成不会按当前业务组重新解析历史订单。
- `bd_quarterly_commissions` 依次使用 `draft`、`generated`、`reviewed`、`confirmed` 状态。
  预览不写入业务表；正式生成可以重建未审核周期；已确认周期及其明细不可重算或修改。
- 每笔订单在同一季度通过唯一约束只生成一条明细。人工调整必须带金额和原因，并进入
  `bd_commission_adjustments` 与审计日志。
- 已确认季度中的订单更正会把旧 BD 的反向差额和同季度新归属的正向差额写入下一季度草稿；
  若订单进入后续季度，则下一季度只记录原已确认贡献的反向差额，后续正式生成再按新订单事实计入。

## 权限与入口

`/bd-commissions` 使用 `settlement.read`：BD 只能查看自身历史归属快照对应的明细，超级管理员
可以查看全部周期。正式生成、规则版本、人工调整、审核和确认均在 Application Service 再次限制为
超级管理员，不能只依赖 Blade 隐藏按钮。Dashboard 控件和应用侧栏均提供报表入口；页面顶部通过
`page-back.blade.php` 返回 Dashboard，并使用命名路由和 `wire:navigate`。

## 环境与验收

本 PR 新增数据库迁移，不新增环境变量、外部服务或队列任务。本机必须先运行 PR6 定向测试和
完整 `composer ci:check`，再构建 Vite。UAT/Production 尚未执行迁移或人工验收；部署前应备份数据库，
执行迁移后确认规则版本、历史订单快照、季度生成/审核/确认、人工调整和更正差额抽样结果。
