# Phase 6 多维查询、数据看板与配置中心

## 交付范围

Phase 6 提供以已完成订单为事实的固定 9 维 AND 查询、最近导出记录、按结果规模即时
或异步的 Excel 导出、真实数据看板与 PDF/HTML 导出，以及机构、定向字典、
白名单系统参数、内部用户和高风险配置历史管理。完整 Order/Settlement CRUD、
通用查询构建器、CQRS 和预聚合读模型不在本阶段。

内部用户与通知负责人配置统一从 `/admin/configuration/users-and-notifications` 进入，页面提供“用户与权限”和“通知设置”两个标签；旧的用户管理和通知设置命名路由保留为带标签参数的重定向，避免书签和既有入口失效。

## 多维查询

- 一级页面为 `/reports/search`，所有启用中的内部用户可访问。
- 顶部搜索回车进入统一结果页，同时展示客户和已完成订单项目；超级管理员还会看到
  代理商结果。下拉菜单继续保留按客户、订单项目和代理商定向搜索的入口。
- 筛选维度为成交日期区间、成交时段、客户、代理商、施术项目、机构、翻译姓名、
  成交金额区间和护照号；全部为 AND。
- 护照号由 Customer 使用现有规范化 HMAC 盲索引精确定位，不解密扫描、不返回敏感
  字段。结果默认每页 50 条，只允许成交时间、客户、代理商、项目、机构和金额排序。
- `completed_at` 保存真实成交时间，`completion_precision` 区分历史 `date` 与新
  数据 `datetime`；历史 `completed_on` 按 Asia/Shanghai 当地日期零点回填，当前
  版本继续双写旧列以支持镜像回退。
- 多维查询页面不再显示常用查询入口，既有 report_saved_queries 数据暂不删除，需另行
  确定归档或迁移方案。结果不超过同步阈值时直接生成并下载，超过阈值时进入队列；
  导出使用私有磁盘、创建者下载授权、SHA-256 和 24 小时过期清理。

## 机构月度销售额

- 一级页面为 `/reports/institution-sales`，仅超级管理员和 BD 可访问；客服不开放该页面，
  直接访问返回 403。BD 的结果由 Order 报表读取器按当前有效业务范围过滤，超级管理员查看
  全部范围。
- 页面支持月份选择和机构名称筛选，按机构展示客户数、有效订单数和销售额，并展示当前筛选
  结果的合计。机构名称复用 Config 的 `ReportConfigReader`，不跨模块读取机构 Model。
- 统计契约固定为：`orders.institution_id` 分组，`occurred_on` 落在目标自然月，
  `status=completed`、`record_status=active`，排除软删除和 `occurred_on` 为空的订单，
  金额使用数值字段 `amount_krw`。完成日期 `completed_at` 不参与该报表的月份归属。
- 页面和 XLSX/PDF 导出使用同一次 Report 汇总服务结果；Excel 的客户数、订单数和金额写入数值
  单元格，PDF 复用统一正式财务单据模板，并通过现有私有导出下载控制器和权限指纹校验提供下载。
  导出不进入订单明细异步队列，也不新增汇总表、migration 或预聚合缓存。
- 当前版本暂不提供趋势、同比环比、邮件、月报冻结或机构明细钻取。真实规模验收时应对
  `occurred_on` 聚合执行 `EXPLAIN ANALYZE`，根据实际计划再决定是否新增索引。

## 看板口径

看板支持今日、本周、本月、本季度、本年和自定义区间，并使用紧邻的等长前一周期
计算环比。前期值为零时显示 `—`。六项指标为新增客户、成交金额、营收、在跟进
客户、待回访客户和待结算金额；当前营收口径与区间内已完成订单成交金额一致。

八项图表为代理商推广费排行、月度推广费趋势、当前等级分布、客户来源分布、月度
消费趋势、复购率、跟进完成率和机构营收对比。复购率以区间内完成订单客户计算；
跟进完成率是区间内完成提醒数除以到期提醒总数；待结算金额排除已结清结算单覆盖
的推广费。

聚合缓存最长五分钟；缓存异常只记录告警并回退数据库聚合。PDF/HTML 使用同一服务端
SVG/表格快照，并保留相同区间、指标和快照生成时间。
缓存快照中的客户状态、提醒类型和其他系统标签只保存语言无关标识，页面与导出在请求 Locale 下投影文案，避免中文请求生成的缓存污染韩文输出。报表导出失败保存稳定消息键和命名参数，最近导出列表按当前 Locale 渲染；未知异常仅返回安全通用信息，不展示原始异常正文。
应用镜像在构建阶段从 Debian 的中文、韩文 TrueType 字体合并出独立的
`GNSystemSans-Regular.ttf` 和 `GNSystemSans-Bold.ttf` 供 Dompdf 使用，并在镜像构建与 CI
中校验中文、韩文、`₩`、数字和英文 glyph 以及 Regular/Bold 字形差异；升级已有开发、UAT
或生产实例时必须重建或拉取包含这两份字体的新 app 镜像，
仅重启旧容器不能修复字形缺失。

页面沿用 Phase 1 已确认的经营总览布局，而不是把全部序列平铺为统一图表网格：

- 顶部五项摘要为营收、新增客户、待跟进提醒、代理商推广费和复购率。
- 第二排为月度营收/订单组合图、代理商推广费排行和客户生命周期漏斗。
- 第三排为今日待办、最近客户和最近月结进度。

这些区域都由 Report 通过数据所有者的只读契约组装。生命周期按截至区间结束时的
去重客户计算：建档、已预约、生命周期状态已到院、已有跟进记录和至少两笔完成订单；
最近客户展示其真实来源、当前状态、建档日期和负责人。原有八项分析序列继续保留在
同一不可变快照中供服务端导出使用。

## 总览数据下钻

PR5 为经营总览的可下钻入口复用现有命名路由和页面权限：营收、复购率及月度营收/订单
趋势进入多维查询并携带当前 `completedFrom`/`completedTo`；新增客户和最近客户列表进入
客户管理并携带 `createdFrom`/`createdTo`。客户列表的日期边界按 Asia/Shanghai 的自然日
解释；Dashboard 预设区间的下钻也按目标页面现有的日期粒度截止到所选结束日。代理商排行在超级管理员可见时进入对应代理商详情，提醒入口继续复用 Reminder 的
可见范围，月结入口仅对超级管理员显示；BD 季度提成入口对超级管理员和 BD 开放，BD 只读自身
归属。看板不新增数据库表、预聚合或权限模型。

## 团队管理 PR2

Report 提供 `/team-overview` 一级页面，用于组织和团队工作视角，不替代 Dashboard 的经营 KPI。
BD 仅能查看当前有效业务组，超级管理员可以查看全局业务组并下钻到单组详情；客服不开放该页面。
页面只通过 Customer、Reminder、Order 的只读 Application Contract 组合业务组总量、负责人工作量、
客户生命周期、提醒和自然月成交统计，并复用已有客户列表、提醒中心和业务组详情路由，不直接读取
其他模块的 Model 或 Builder。本能力不新增表、migration、缓存或后台任务。成交总额按订单
`occurred_on`、有效记录和订单归属快照统计，负责人离组或代理商转组不会重写历史团队口径；空客户状态
单独计入 `unset`。超级管理员选择业务组时顶部 KPI 切换为该组，关注卡片会分别下钻到逾期提醒、未分配客户
和待处理移交筛选。
团队统计的客户/提醒范围包含当前有效期内的全部代理商，暂停或终止状态只影响“有效代理商数”展示；
失效客服负责人名下的客户单独计入负责人异常。超级管理员单组下钻会把业务组编号传给客户和提醒页面，
目标页面及 Order 读取器会重新校验当前访问权限。历史完成订单缺少归属快照时，发布前使用
`app:backfill-order-attribution-snapshots` 先预览异常，确认唯一匹配后再用显式 `--apply --actor --reason`
逐单写入并审计，无法匹配的订单不会被自动猜测。

## 配置与数据所有权

- Config：机构、施术项目/翻译语种字典、查询分页数和看板刷新秒数。
- Customer：客户状态和流转。
- Agent：类型代码、政策体系和等级。
- Settlement：机构费率、代理商特批和月结周期。
- Auth：内部用户邀请、三档业务角色、业务组成员有效期、启停与会话撤销。

订单和预约保存可空字典引用及原始名称快照；停用项不再用于新录入，但历史展示不受
重命名影响。用户停用会递增会话版本，使数据库或 Redis 中的旧会话都失效；禁止
停用自己或最后一个启用中的超级管理员。

Agent、Customer、Settlement 各自保存 JSONB 配置快照并公开历史、差异和回滚
Application Contract。回滚在所有者事务中保存回滚前版本、恢复目标、写入新的
回滚记录、失效缓存并审计；订单推广费快照、结算文档和已结算内容不重新计算。

## PR6 BD 季度提成入口

Report 只提供 Dashboard 和侧栏导航，不读取 BD 季度提成表。季度规则版本、预览、正式生成、
审核、确认、人工调整和订单更正差额均由 Settlement 页面及其 Application Service 负责；
超级管理员可操作完整流程，BD 只能在自己的业务归属范围内查看已生成历史。直接访问 URL、
Livewire 动作和下载仍由 Settlement 的权限范围重新检查。

## 跨模块与运行要求

Report 只协调数据所有者的只读 Application Contract/Data；Order 执行分页事实
查询，其他模块负责筛选解析、批量名称和所属聚合。Config 页面同样只调用数据所有者
公开的写入/历史契约。跨模块不暴露 Model 或 Builder。

生产必须运行 Queue 与 Scheduler、配置 SMTP，并把私有导出目录持久挂载。发布使用
兼容迁移与双写代码；回退旧镜像继续依赖保留的 `completed_on`。完整门禁与 UAT
至少包括：

```bash
docker compose exec app composer ci:check
docker compose exec vite npm run build
```

真实规模 UAT 还需执行 `EXPLAIN ANALYZE`，目标为多维查询 < 1 秒、看板首屏
< 2 秒；未达标先调整索引和查询，预聚合另行立项。
