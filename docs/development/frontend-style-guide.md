# 前端页面风格与格式规范

本文件是 GN-System 已认证业务页面的视觉、版式和交互规范。新建或明显调整页面时，
必须以本文件为设计基线；现有页面如与本规范不一致，应在涉及该页面的变更中逐步收敛，
不得为了统一样式而扩大无关重构范围。

## 规范来源与权威边界

当前前端风格由三层共同组成：

1. `resources/css/app.css`：共享字体、颜色变量、布局类、卡片、导航、表格和响应式基线，
   是视觉 token 和公共 CSS 的实现来源。
2. Flux UI 组件：表单控件、按钮、菜单、图标等交互控件的基础样式和语义变体。
3. `resources/views` 下的 Blade / Livewire 页面：页面结构、业务文案、页面级布局和交互组合。

本文件统一说明前端应遵循的页面风格和格式；`docs/development/ui-navigation.md` 专门约束
页面层级、返回按钮和内部导航；`AGENTS.md` 是开发流程与代理工作规则，不是视觉设计稿。
如果实现与文档冲突，先以当前代码和测试确认事实，再同步修正文档或实现。

## 页面结构

### 一级页面

一级页面是侧栏直接入口，例如客户管理、代理商管理、订单中心、多维查询、配置中心和月结中心。
业务页面使用统一的 `crm-section-header`：

- 标题：`text-2xl font-bold tracking-tight`，使用业务名称，不显示技术模块名。
- 描述：`mt-2 text-sm text-zinc-500 dark:text-zinc-400`，说明用途、范围或操作限制。
- 一级页面不重复显示“报表”“Config”“Phase”等技术 eyebrow；标题已经能够表达页面所属业务。

### 二级、三级页面

二级、三级是从业务页面继续进入的完整页面。除遵守
[`ui-navigation.md`](ui-navigation.md) 的返回导航规则外，页面顶部按以下顺序排列：

1. `x-page-back` 返回按钮；
2. 弱化的 eyebrow：`text-xs font-medium text-zinc-400`，使用简短的业务父级路径；
3. 标题：`mt-1 text-2xl font-bold tracking-tight`；
4. 描述：`mt-2 text-sm text-zinc-500 dark:text-zinc-400`。

eyebrow 只用于帮助用户定位当前页面，不重复标题，也不暴露模块目录、类名、阶段编号或内部
技术实现。弹窗、局部组件和认证流程不强行套用完整业务页面的标题层级。

## 文案与字体

- 全局默认字体使用 `Instrument Sans`，中文回退到 `PingFang SC`、`Microsoft YaHei` 和系统无衬线字体。
- CRM 页面基准字号为 `14px`，行高约 `1.55`。正文优先使用 `text-sm`，辅助信息使用 `text-xs`。
- 页面主标题统一使用 2xl、粗体、紧字距；卡片标题通常使用约 14.5px、半粗体；表格正文和元数据可使用较小字号。
- 业务名称、状态和数字应保持易读；只读客户、内部用户和代理商姓名遵循
  [`ui-navigation.md`](ui-navigation.md) 的半粗体规则，录入控件不额外加粗。
- 标题和描述使用用户能理解的业务语言。描述应说明“能做什么”或“有什么限制”，避免出现
  `Phase`、模块命名空间、类名、Redis、HMAC、队列等实现词；安全或操作限制确实需要说明时，改写成用户可理解的业务表述。
- 中文界面保持简洁，使用全角中文标点；父级路径或轻量上下文可用 `·` 分隔，不使用多层技术路径。

## 应用壳与布局

当前 CRM 应用壳的基线来自 `resources/css/app.css`：

- 桌面侧栏约 `232px`，固定在视口高度内；顶部栏约 `60px`，使用浅色边框分隔。
- 内容区桌面内边距为约 `18px 22px 24px`；窄屏收窄为约 `14px`。
- 品牌区使用约 `40px` 的圆角品牌标记、简短产品名和副标题；不在业务页面重复放置品牌信息。
- 侧栏导航项最小高度约 `42px`，圆角约 `9px`，图标约 `18px`。当前项使用浅青绿色背景、强调色文字和左侧强调条。
- 页面内容优先使用纵向分区。相关内容放在同一张卡片中，卡片之间保持一致间距，不使用无意义的嵌套面板。

## 颜色、边框与卡片

- 主色使用 CRM 共享 token：`--crm-primary`、`--crm-primary-strong` 和 `--crm-primary-soft`；默认主行动作采用青绿色调。
- 状态色按语义使用：成功为绿色，警告为琥珀色，错误或危险操作为红色，辅助信息可使用蓝色或紫色。
- 优先使用 Tailwind 的 `zinc`、`teal`、`blue`、`amber`、`green`、`red` 语义色或共享 CSS 变量，
  不在页面模板中随意新增十六进制颜色。
- 白色表面、`zinc` 边框、轻阴影和约 `12px` / `rounded-2xl` 圆角是业务卡片基线。
  常用卡片应优先复用 `.crm-card`；页面级表单和配置卡片保持“边框 + 白色表面 + 轻阴影”的组合。
- 所有新增浅色背景、文字和边框都必须同时检查 dark variant；不能只在浅色主题下可读。
- 危险操作必须使用危险语义和清晰文案，不用主色按钮伪装删除、撤销或不可逆操作。

## 表单、按钮与反馈

- 表单控件优先使用 Flux 的 `flux:input`、`flux:select`、`flux:textarea` 和 `flux:button`，保持默认可访问结构和语义变体。
- 每个输入控件必须有可见 label 或等价的可访问名称；placeholder 只能补充示例，不能替代 label。
- 表单按业务分组，常见布局为响应式 grid；桌面多列，窄屏自动单列。不要通过固定宽度迫使页面横向滚动。
- 长操作必须提供进行中状态，例如 `wire:loading`、禁用重复提交或明确的队列状态；失败时给出页面内可理解的错误反馈，不能静默吞异常。
- 成功提示使用绿色语义，校验或系统错误使用红色语义，风险提醒使用琥珀色语义；提示应靠近相关操作或页面顶部。
- 内部页面跳转使用命名路由和 `wire:navigate`；文件下载使用普通下载链接，不使用 `wire:navigate`。

### 临时通知与持续提示

- 保存、审核、驳回、结清、进入队列、重试提交和刷新报价等一次性结果统一使用 Flux Toast，
  仅使用 `success`、`warning`、`danger` 三种语义；业务页面不再重复渲染顶部 session 消息。
- 会持续影响当前操作的生成状态、数据缺失、审核禁用和配置阻断必须保留为页面顶部横幅，
  同时说明发生了什么、对当前操作的影响以及下一步动作。横幅使用稳定且唯一的业务 ID。
- 红色严重状态或会禁用关键操作的黄色状态首次出现时，可由 Livewire 派发
  `business-alert-focus`，前端仅将该横幅平滑定位一次；轮询、普通重渲染、成功状态和字段校验
  不得重复定位。字段校验错误仍定位到具体字段。

## 卡片、指标、表格与空状态

- 指标卡使用统一的 `.crm-metrics` / `.crm-metric` 基线：桌面可多列展示，窄屏至少保持两列或转为可读的纵向布局。
- 卡片标题行保持标题、辅助链接和操作按钮的对齐；操作不应被挤出容器或在窄屏覆盖正文。
- 表格使用 `.crm-table-wrap` 负责横向滚动、`.crm-table` 负责表格基线。表头弱化、行使用细分隔线，悬停只提供轻量背景反馈。
- 表格列按内容设置合理的 nowrap；长文本应有明确截断或可展开方案，不能无提示地破坏布局。
- 空状态说明当前没有数据的原因或下一步操作，避免只显示“暂无数据”。
- 复杂流程可以使用步骤条、上传区等专用布局，但仍需沿用共享颜色、圆角、间距和状态语义。

## 响应式与可访问性

- 以约 `767px` 为窄屏基线：收紧内容内边距，隐藏非必要的顶栏辅助文字，表单控件转为单列，表格允许横向滚动。
- 任何页面都不能因为标题、按钮、筛选条件或表格造成不可控的横向溢出；图表等确需最小宽度的区域必须被可滚动容器包裹。
- 交互控件必须有键盘焦点反馈；图标按钮提供可访问名称，装饰性图标标记为隐藏或配合文字。
- 颜色不是唯一的状态表达方式；状态同时使用文字、图标或其他清晰标识。
- 深色主题至少检查页面标题、描述、卡片、输入框、表格、提示和 hover/focus 状态的对比度。

## 新页面验收清单

提交前至少检查：

- 页面属于一级还是二级/三级，标题、eyebrow 和返回按钮层级正确；
- 标题和描述使用业务文案，没有不必要的技术术语；
- 卡片、表单、表格、提示和按钮复用了现有组件、token 和语义色；
- 浅色、深色和窄屏布局可读，没有横向溢出；
- 内部跳转、返回标签和目标命名路由符合导航规范，下载链接不使用 Livewire 导航；
- 相关 Feature 测试覆盖页面文字、路由和关键交互；
- 至少运行 `docker compose exec app composer docs:check`，涉及前端构建时再运行 `docker compose exec vite npm run build`。
