# 页面层级与返回导航

本规则适用于 GN-System 已认证后的完整业务页面。

视觉层级、字体、颜色、卡片、表单、表格和响应式格式见
[前端页面风格与格式规范](frontend-style-guide.md)；本文件只约束页面层级、返回按钮和内部导航。

## 页面层级

- 一级页面是侧栏直接入口，例如总览、主动提醒、客户管理、订单、多维查询、代理商、月结中心和配置中心。一级页面不显示
  “返回上一级”按钮。
- 二级页面由一级页面进入，例如新建客户、客户详情、配置中心下的数据导入与迁移、业务配置和账户设置。
- 三级页面由二级页面进入，例如从客户详情进入的编辑客户页，以及数据导入与迁移下的基础配置导入和历史数据迁移。
- 弹窗、局部组件和登录、找回密码、两步验证等认证流程不按业务页面层级处理。

## 返回按钮规则

- 每个二级、三级完整页面都必须在主要内容顶部提供清晰可见的返回按钮。
- 返回目标必须使用稳定的命名路由指向明确父页面，不使用浏览器历史或
  `javascript:history.back()`，避免从外部链接或刷新后返回错误位置。
- 二级客户页面返回对应一级列表；配置详情返回配置中心；数据导入与迁移下的基础配置导入和历史数据迁移返回“数据导入与迁移”；用户与权限/通知设置统一页返回配置中心；三级编辑页面返回对应详情；
  账户设置返回总览。
- 统一使用 `resources/views/components/page-back.blade.php`，按钮采用蓝色实心样式、
  左箭头、`wire:navigate`，标签写明具体目标，例如“返回客户管理”。
- 共享返回组件保留明确命名父路由作为兜底；`resources/js/app.js` 会在同一父路径的 `wire:navigate` 返回中恢复来源页面的查询参数、分页状态和滚动位置，不能依赖浏览器历史代替父路由。
- 新增完整页面时，Feature 测试必须验证返回按钮文字和父级路由。

## 关键姓名展示

- 客户、内部用户和代理商姓名在列表、详情标题、关联记录及时间轴等只读展示位置统一
  使用半粗体重点显示。
- 表单输入框和下拉选项保持控件默认字重，避免影响录入与选择体验。
