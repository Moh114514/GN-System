# Phase 5 UAT 验收手册

本文用于在独立 UAT 环境验收历史数据导入、月结结算和主动提醒。验收数据必须脱敏，
并使用 `UAT-P5-YYYYMMDD` 前缀，避免与其他验收批次混淆。

UAT 结果只能证明对应 RC 在该 UAT 环境通过，不代表生产环境已经验证。RC 创建、部署、
回退和镜像晋级遵循[UAT 测试版本与正式发布流程](release-management.md)。

## 1. 验收前检查

由发布或运维负责人记录以下证据：

- RC 标签、标签提交和 app/web 镜像摘要；
- `/srv/gn-system/releases/current` 中的当前版本；
- `/up`、`/health` 和 `/health/operations` 均成功；
- UAT 的 Queue 和 Scheduler 容器正常，运维健康页不存在过期心跳；
- 使用已确认 TOTP 的超级管理员账号，并准备一个普通内部用户账号用于权限验证；
- `DINGTALK_ENABLED=false`，Webhook 和 Secret 为空。

UAT 必须使用专用数据库、Redis、私有文件目录和端口。不得复制生产凭据或导入未脱敏
文件。执行前记录数据库备份状态；本手册不要求也不授权直接修改数据库。

## 2. 准备验收数据

### 2.1 确定月结周期

在“月结中心”记录当前边界日、触发时间和时区。最近已结束周期是“最近一次边界的前一个
连续周期”。例如边界为每月 1 日 09:00，且当前时间已经过本月边界，则最近已结束周期
为上一个自然月。

本次新月结使用的已完成订单必须落在该周期内。历史导入中的月结汇总应使用更早月份，
不要先导入同一周期的历史月结，否则系统会按设计阻止新月结覆盖历史数据。

### 2.2 建立最小业务链路

使用同一 `UAT-P5-YYYYMMDD` 前缀完成以下准备：

1. 在“配置中心 → 代理商与推广费”建立政策体系和至少两个等级。较高等级的月推广费
   门槛应高于基础等级，并低于本次预期推广费，以产生等级建议。
2. 为基础等级和验收机构配置在订单完成月份已生效的机构费率。
3. 在“代理商”建立合作中的验收代理商，并分配基础等级；等级生效月不得晚于订单月份。
4. 在“客户管理”建立代理商渠道客户，负责人选择本次验收用户。
5. 从客户详情进入“登记订单”，建立一笔代理商订单：
   - 机构与费率配置一致；
   - 完成日期位于最近已结束周期；
   - 状态为“已完成”；
   - 金额使用便于手工核算的整数。
6. 记录订单金额、费率和页面固化的推广费，作为月结核对基准。

如果使用 `GN-System_Phase5_UAT.xlsx`，先核对它只包含脱敏数据、扩展名正确，并符合
[Phase 2 导入字段和生命周期](../modules/phase-two-core-data.md)。文件不提交到 Git。

## 3. 历史数据导入验收

进入“数据迁移”，打开浏览器开发者工具的 Console 和 Network。

| 编号 | 操作 | 预期结果 |
|---|---|---|
| IMP-01 | 选择一个合法 XLSX 或 CSV | 显示上传进度；Console 不出现 `reading 'name'` 或 Livewire Expression Error |
| IMP-01A | 查看上传前基础数据状态并下载两个模板 | 代理类型、机构、直销来源均显示已就绪；结构示例和可导入模拟数据为两个不同文件 |
| IMP-01B | 上传逗号分隔 CSV 并查看文件预检 | 显示英文逗号、编码、表头行和识别到的业务类型 |
| IMP-01C | 上传分号分隔或无法识别表头的 CSV | 批次明确失败并提示“表头未识别/分隔符可能错误”，不得显示为 `codebook` 成功 |
| IMP-02 | 上传 2–5 个合法文件 | 只创建一个批次，文件数正确，页面进入解析/校验状态 |
| IMP-03 | 上传一个大于 12MB 且不超过 20MB 的合法文件 | 临时上传成功，不再被 Livewire 默认 12MB 限制拒绝 |
| IMP-04 | 上传 PDF 或其他不支持类型 | 页面显示明确格式错误，不创建批次 |
| IMP-05 | 上传超过 20MB 的文件 | 页面显示明确大小错误，不创建批次 |
| IMP-06 | 一次选择超过 5 个文件 | 页面显示批次数量错误，不创建批次 |
| IMP-07 | 查看解析结果和前 50 行 | 有效、警告、错误计数与文件内容一致 |
| IMP-08 | 补充未知机构或直销来源后重新校验 | 映射保存成功，批次重新解析，计数按修正结果更新 |
| IMP-09 | 对错误或重复候选填写原因并忽略 | 裁决结果和原因可见，未填写原因时明确拒绝 |
| IMP-10 | 对零错误、零待处理批次执行正式导入 | 批次原子完成；客户、订单等目标记录可查 |
| IMP-11 | 在 24 小时内回滚未被后续修改的批次 | 批次变为已回滚，导入记录撤销 |
| IMP-12 | 先修改某条已导入业务数据再尝试回滚 | 回滚被阻止，并显示阻塞表和记录标识 |

保存批次 UUID、文件名、文件大小、计数、错误报告和关键页面截图。不要把含敏感原始数据
的错误报告发送到非受控位置。

## 4. 月结与结算单验收

1. 在“月结中心”点击“生成最近已结束周期”，记录批次 UUID 和页面显示的周期。
2. 等待进度完成，确认 Queue/Scheduler 健康，代理商处理数和失败数与准备数据一致。
3. 再次点击生成，确认复用同一周期批次，没有重复月结或重复明细。
4. 打开验收代理商的月结详情，逐项核对：
   - 消费合计等于该周期内符合条件的已完成代理商订单；
   - 推广费合计等于订单完成时固化的推广费，不按当前配置重新计算；
   - 明细中的项目、完成日期、金额和费率快照正确。
5. 驳回时留空原因，确认系统拒绝；填写原因后确认状态为“已驳回”。
6. 审核时输入 `0` 或负数，确认系统拒绝；输入正数 KRW/CNY 汇率后审核通过。
7. 下载 Word 和 PDF，核对代理商、周期、消费、推广费、汇率和人民币应付金额一致；
   下载批次 ZIP，确认包含预期文件。
8. 点击“确认信息并结算”，确认状态为“已结清”；再使用“受控状态更正”，填写原因，将其撤回为“已通过”，确认结清人、结清日期和确认时间被清空且审计日志记录前后状态与原因。
9. 将状态更正为“待审核”，确认审核人、审核时间、结清字段和人民币应付金额被清除，并可重新填写汇率后再次审核。
10. 如果出现等级建议，分别验证：
   - 未经人工复核不会改变当前等级；
   - 批准后代理商详情显示新等级从下月生效；
   - 选择维持原等级时不产生新的等级生效记录。
10. 修改月结边界日或时间，确认页面提示新配置的生效日，已生成周期仍保留旧配置快照。
11. 准备一名在目标历史周期内合作、但当前已暂停或终止的代理商，以及一名在该周期结束后才加入的代理商；生成往期月结，确认前者参与、后者不参与。
12. 准备一名周期内没有已完成订单的代理商，确认月结显示为“已生成”的零订单月结，可以正常审核，不会被“明细为空”误判为未生成。
13. 在已有月结批次的周期重复点击生成，分别记录处理中、已完成和部分失败提示，确认不会重复派发；部分失败只能通过“重试失败项”处理。
14. 修改边界日使配置从 1 日切换到 15 日或反向切换，核对历史列表与已生成批次的起止日期连续、无重叠、无遗漏。
15. 为已有旧汇率的月结制造报价服务失败，确认页面不显示成功提示、汇率数值保持不变且状态为保留旧汇率。

代理商失败重试、千条明细五分钟内完成和事务一致性由自动化测试覆盖。人工 UAT 不通过
直接改库、破坏费率快照或伪造失败状态来测试这些路径。

## 5. 主动提醒验收

### 5.1 系统和手工提醒

1. 打开“主动提醒”，确认第 2 节已完成订单产生术后 1/7/30/90/180 天系列提醒，
   过去且不应再执行的项目不作为待处理任务显示。
2. 新建一条数分钟内到期的一次性提醒，关联验收客户并分配给验收用户。
3. 新建一条周期提醒并保存为个人模板，再从该模板创建提醒，核对标题和建议方向。
4. 分别对独立提醒执行延期、转交、完成和关闭；延期必须填写有效时间和原因。
5. 在“提醒历史”核对生成、延期、转交、完成和关闭事件及操作时间。

### 5.2 规则、权限与通知降级

1. 超级管理员进入“配置中心 → 主动提醒规则与模板”，确认页面显示“钉钉通知未启用；
   站内提醒仍正常运行”。
2. 建立一个只作用于验收客户负责人的日期偏移或固定周期规则，等待 Scheduler 运行，
   确认只生成一条符合范围的任务；再次运行调度不得重复。
3. 编辑模板后确认已生成提醒内容不被回写，新提醒使用新模板内容。
4. 使用普通内部用户登录：
   - 可以看到分配给自己或自己创建的提醒；
   - 看不到其他用户的提醒；
   - 无法进入月结中心和提醒全局配置；
   - 可以完成、延期或转交自己有权处理的提醒。
5. 到期通知处理后，站内任务保持可用，钉钉状态明确为“未启用”，不得显示为已发送。

真实钉钉发送、重试和签名凭据不在本轮 UAT 范围。需要验收时必须另行配置沙箱机器人，
不得复用生产 Webhook 或 Secret。

## 6. 结果记录与结束条件

每个用例记录：执行人、时间、RC、UAT 地址、输入标识、预期、实际结果、截图或下载文件
证据、通过/失败和缺陷编号。以下条件全部满足才可判定 Phase 5 UAT 通过：

- 上传控制台异常消失，合法文件可进入解析队列；
- 20MB 单文件和 5 文件批次的业务限制与运行层配置一致；
- 月结金额、推广费快照、审核、文档和结清闭环正确；
- 主动提醒生命周期、权限隔离和钉钉关闭时的站内降级正确；
- `/health/operations` 在验收期间持续健康；
- 没有未解释的数据差异、高严重度错误或敏感数据泄露。

当前业务页面没有完整删除能力。验收数据默认按统一前缀保留；如必须清场，由授权运维
人员按已验证的 UAT 备份恢复流程执行，不得使用 `migrate:fresh`、`db:wipe`、
`docker compose down -v` 或直接删除业务表记录。
