## 1. 系统概述与背景

### 1.1 一句话说明

> **把目前散落在 4 份 Excel 表里的客户、代理商、订单、结算数据，搬到一个网页系统里统一管理，让跟进不漏单、结算不出错、数据能看懂。**

### 1.2 业务背景

我们是一家**代理医美/医疗机构**，客户多通过**代理商（渠道商）推荐**到院消费，业务涉及涉外客户（需要翻译服务、登记护照号）。目前所有客户跟进、代理商结算、月度汇总都依赖人工 Excel 维护，存在以下痛点：

| 痛点 | 现状描述 | 影响 |
|------|----------|------|
| 数据分散 | 4 份 Excel 分别由不同人维护，信息对不上 | 客户跟进遗漏、重复联系 |
| 手工易错 | Excel 公式经常出现 `#VALUE!` 等错误 | 推广费算错、代理商投诉 |
| 查询困难 | 想按"某代理商+某项目+某时段"查数据要翻半天表格 | 决策慢、响应客户慢 |
| 提醒靠记 | 术后 1/7/30 天回访全靠人脑记 | 客户体验差、复购率低 |
| 看不到全局 | 老板想知道"本月各机构营收对比"要等财务统计 1 天 | 管理滞后 |

### 1.3 系统目标（Why）

**业务目标**：
1. **效率提升**：月结汇总从"半天"降到 **5 分钟以内**
2. **错误清零**：彻底消灭 Excel `#VALUE!` 类错误
3. **客户体验**：术后回访准时率从"靠记"提升到 **100% 自动提醒**
4. **决策赋能**：管理层可**实时**看到核心经营数据，不再等日报

**用户目标**：
- 客服：不用再翻 Excel 找客户，系统自动提醒今天该回访谁
- 财务：月结一键生成，结算单自动出 Word/PDF
- 代理商管理员：推广费自动算，等级自动判，不再对账扯皮
- 老板：打开首页就能看营收、转化、Top 客户

### 1.4 范围与非目标（Non-goals）

✅ **本项目要做**（In Scope）：
- 客户、代理商、订单、结算的**内部管理系统**
- 数据从 Excel 迁移到 Web 系统
- 内部员工使用的管理后台

❌ **本项目不做**（Out of Scope / Non-goals）：
- **不做**面向终端客户的 App/小程序（客户不直接登录系统）
- **不做**在线支付/收款（结算单只生成，不走支付通道）
- **不做**代理商自助门户（代理商不直接登录，由内部代为管理）
- **不做**医疗电子病历/施术记录系统（只记录"做了什么项目、金额"，不记录医疗细节）
- **不做**营销自动化（短信群发、社群运营等）
- **不做**多语言界面（仅中文，但客户姓名/护照号等字段支持多语言字符）
- **不做**灵活自定义表格/自定义字段（列表与表单字段固定，不做列配置与动态字段；多维查询仅支持固定 9 维筛选与常用筛选保存）
- **不做**无限制的自由文本提醒（提醒规则仍需有结构化触发条件与适用对象，客服自定义提醒可在模板库基础上修改或完全新建）

> 💡 明确 Non-goals 是为了防止范围蔓延。如果有相关需求，应作为独立项目立项。

### 1.5 成功指标（如何判断系统做成功了）

| 指标 | 基线（现状） | 目标值 | 衡量方式 |
|------|--------------|--------|----------|
| 月结耗时 | 半天（4 小时） | ≤ 5 分钟 | 系统日志 |
| Excel 错误率 | 频繁出现 `#VALUE!` | 0 | 财务反馈 |
| 术后回访准时率 | 不可统计 | ≥ 95% | 提醒中心记录 |
| 数据查询响应 | 翻表 10-30 分钟 | ≤ 3 秒 | 系统日志 |
| 管理层看数延迟 | 等 1 天日报 | 实时 | 看板刷新 |

## 2. 用户角色与使用场景

### 2.1 用户角色定义

| 角色 | 职责 | 使用频率 | 关键诉求 |
|------|------|----------|----------|
| **超级管理员** | 系统配置、权限分配、全量数据 | 每周 | 配置灵活、权限可控 |
| **客服专员** | 客户建档、跟进、回访 | 每天 | 提醒不漏、操作快 |
| **客服主管** | 团队管理、客户分配、质量检查 | 每天 | 看团队绩效、能调配 |
| **代理商管理员** | 代理商档案、推广费核算、月结 | 每月集中 | 算得准、对得清 |
| **财务专员** | 月结审核、结算单生成、发放 | 每月集中 | 一键出单、可追溯 |
| **机构对接人** | 录入到院记录、施术项目 | 每天 | 录入快、不重复 |
| **管理层（老板/总监）** | 看数据、做决策 | 每天/每周 | 一眼看懂、能下钻 |

### 2.2 典型使用场景（User Story 格式）

> 格式：**作为 [角色]，我希望 [行为]，以便 [价值]**

#### 场景 1：客服日常跟进
> 作为**客服专员**，我希望**早上打开系统就能看到今天要回访的客户清单**，以便**不遗漏任何一个术后客户，提升复购率**。

#### 场景 2：代理商月度结算
> 作为**财务专员**，我希望**每月 1 号点一下"生成本月结算"，系统自动汇总每个代理商的推广费并生成结算单**，以便**把原来半天的活儿压缩到 5 分钟，还不出错**。

#### 场景 3：老板看数据
> 作为**管理层**，我希望**打开首页就能看到本月营收、各机构对比、Top10 客户**，以便**快速判断经营状况，不用等财务做日报**。

#### 场景 4：多维查询
> 作为**客服主管**，我希望**能按"某代理商+某项目+某时段"组合查询客户**，以便**分析渠道质量，优化资源分配**。

#### 场景 5：Excel 历史数据迁移
> 作为**代理商管理员**，我希望**把过去 2 年的 4 份 Excel 一键导入新系统**，以便**保留历史数据，新系统上线即有完整记录**。

#### 场景 6：术后自动提醒
> 作为**客服专员**，我希望**客户术后第 1/7/30 天系统自动提醒我该做什么回访**，以便**按标准流程跟进，提升客户满意度**。

#### 场景 7：等级调整
> 作为**超级管理员**，我希望**能维护政策体系与等级、配置佣金规则（每等级独立一套、支持代理商个性化覆盖）**，以便**根据业务政策灵活调整，且不影响历史已结算数据**。

## 4. 业务流程说明

### 4.1 客户全生命周期流程（核心主线）

```
建档 ──► 预约 ──► 到院 ──► 回访 ──► 复购
 │        │        │        │        │
 ▼        ▼        ▼        ▼        ▼
新线索    已预约    已到院    已施术   已复购
已联系    已确认             (术后1/7/30天提醒)

5 个阶段（宏观）× 7 档状态（微观）
```

**状态流转规则**：
- 由客服/机构对接人在客户详情页**手动点击"变更状态"**触发
- 系统校验目标状态是否符合 5 阶段顺序，**不可越级**（如不能从"新线索"直接跳到"已施术"）
- 每次状态变更必须**记录谁、何时、为何变更**
- 特殊情况（如客户退单）可由主管**手动回退**，需备注原因

### 4.2 代理商结算流程（月度闭环）

```
用户可自定义结算周期与触发时间（配置中心），默认：每月1日 09:00 触发，结算周期为自然月
   │
   ▼
过滤：仅"合作中"状态的代理商参与月结（暂停/已终止跳过）
   │
   ▼
系统自动汇总上月所有"已完成"订单（按代理商月度累计成交金额）
   │
   ▼
按各代理商所属的政策体系 → 等级 → 个性化规则，读取佣金比例/阶梯
   │
   ▼
计算每个代理商的推广费总额（固化当时规则快照）
   │
   ▼
财务专员审核 ──► 不通过 ──► 标记问题 ──► 退回修改
   │
   通过
   ▼
生成结算单（Word + PDF）
   │
   ▼
通知代理商管理员确认
   │
   ▼
归档，进入"已结算"状态
```

### 4.3 主动跟进提醒流程（全场景自动化）

```
【系统内置·治疗前提醒】
客户预约或建档后
   │
   ├─► 术前 N 天：提醒客服"确认客户到店准备/术前注意事项"
   └─► 到院前 1 天：提醒客服"确认客户到店时间与安排"

【系统内置·治疗当天提醒】
客户到店日期当天
   │
   └─► 上午 9:00：提醒客服"今日到院客户接待确认"

【系统内置·术后系列提醒】
客户施术完成（状态变为"已施术"）
   │
   ├─► 第1天：提醒客服"问候恢复情况"
   ├─► 第7天：提醒客服"跟进恢复进度"
   ├─► 第30天：提醒客服"确认效果+引导复购"
   ├─► 第90天：提醒客服"中期效果回访"
   └─► 第180天：提醒客服"长期效果+复购引导"

【可配置·主动跟进规则】（管理员在配置中心维护）
   ├─► 老客户定期回访（如每 90 天）
   ├─► 客户生日 / 节假日问候
   ├─► 复购窗口期提醒（术后 6 个月/1 年）
   ├─► 营销活动触达提醒
   └─► 沉默客户唤醒提醒

【客服自定义提醒】
   └─► 客服自行创建一次性 / 周期提醒（不限场景，可基于模板库快速创建）

所有提醒包含：客户信息、关联项目、空白话术备注区（员工自行编写）、一键标记"已完成"
```

> 💡 提醒**下发至内部员工的提醒中心与钉钉**，目的是提示员工主动跟进后续进度，**不向客户发送任何消息**。话术由员工自行编写，不内置模板。
> 
> 💡 系统内置提醒、可配置规则、客服自定义提醒三层覆盖，确保术前、到院、术后、复购、维护全流程不漏单。
> 
> 💡 提醒规则引擎首期采用**浅深度**（固定触发条件类型 + 适用对象范围 + 空白备注区），不做复杂条件表达式或自由 DSL。

### 4.4 月结生成流程（性能关键）

```
财务点击"生成本月结算"
   │
   ▼
系统后台拆分任务（按代理商并行处理）
   │
   ▼
实时显示进度条（已完成 X/Y 个代理商）
   │
   ▼
全部完成 ──► 生成汇总报告 ──► 通知财务
   │
   ▼
财务下载 Word/PDF 结算单
```

### 4.5 代理商等级升降流程（系统建议 + 人工复核）

```
每月月结流程（按此顺序执行，2026-07-24 评审确认）：
   │
   ├─► 第1步：用代理商**当前等级**的规则结算当月推广费
   │
   ▼
   ├─► 第2步：结算完成后，系统扫描各代理商当月累计推广费/成交金额
   │
   ▼
对照其所属政策体系下各等级的"升降门槛"（如 月推广费 ≥ 10 万 升一档）
   │
   ▼
系统自动计算并标注："本月达到 X 档门槛 / 未达标"
   │
   ▼
生成"等级调整建议"待办，推送至代理商管理员 / 超级管理员
   │
   ▼
人工复核 ──► 不同意 ──► 维持原等级
   │
   同意
   ▼
执行等级变更（**新等级从下月生效**，不影响当月已结算数据，留痕）
```

> 💡 等级升降为**混合模式**：系统按月业绩自动计算并标注门槛达标情况，但**是否实际升降由人工复核决定**。关键时序：**先结算当月（用旧等级）→ 再评估门槛 → 新等级下月生效**（Q1 评审确认，FR-03-03 第 7 点）。等级门槛在配置中心按政策体系/等级维护（见 FR-07-03）。

### 5.1 模块一：Excel 系统化迁移

| 字段 | 内容 |
|------|------|
| **需求编号** | FR-01-01 |
| **需求名称** | Excel 文件上传 |
| **需求描述** | 用户可上传 .xlsx/.xls 格式的 Excel 文件，系统接收并暂存到预处理区 |
| **触发条件** | 用户在"数据迁移"页面点击"上传 Excel" |
| **预期行为** | 1) 支持单/多文件上传；2) 校验文件格式与大小（≤20MB）；3) 上传后显示文件列表与状态；4) 异常文件给出明确提示 |
| **关联角色** | 代理商管理员、超级管理员 |
| **优先级** | 🔴 高 |
| **状态** | ✅ |

| 字段 | 内容 |
|------|------|
| **需求编号** | FR-01-02 |
| **需求名称** | 数据预览与校验 |
| **需求描述** | 上传后系统先解析 Excel，展示前 50 行预览，并标注校验结果（合格/警告/错误） |
| **触发条件** | Excel 上传成功后自动触发 |
| **预期行为** | 1) 自动识别表头与数据列；2) 逐行校验（手机号格式、护照号格式、金额格式、必填项）；3) 错误行标红并显示原因；4) 显示"X 条合格 / Y 条警告 / Z 条错误"汇总 |
| **关联角色** | 代理商管理员 |
| **优先级** | 🔴 高 |
| **状态** | ✅ |

| 字段 | 内容 |
|------|------|
| **需求编号** | FR-01-03 |
| **需求名称** | 数据导入执行 |

## 8. 附录：术语表

| 术语 | 解释 |
|------|------|
| **CRM** | Customer Relationship Management，客户关系管理系统 |
| **代理商** | 也叫渠道商，推荐客户到院消费的合作方，按比例分推广费 |
| **代理商编号** | 全大写、横杠分隔，格式统一为 `简称-类型代码`，**一旦建立永久不变**（即使后续修改类型代码，编号不变）。系统默认类型代码 3 种：`JG`=机构、`GT`=个体户、`KR`=在韩代理；管理员可在配置中心新增自定义类型代码（如 `VIP`、`OS`），代码 2-4 位大写字母数字全局唯一。示例：`SZ-JG`（神州/机构）、`DY-KR`（金导游/在韩，v1.9 统一格式）、`LH-VIP`（刘会长/VIP合伙人）。简称建议：`XY`=企业名、`DY`=导游、`BJ`=商家/老板、`WL`=姓氏等 2-4 位字母数字。默认代码只停不删（FR-07-09） |
| **客户编号** | 规则为 `代理商编号 - 4 位流水号`，如 `SZ-JG-0001`，同一代理商名下客户累计编号，**不分机构**（即同一代理商下无论对应哪些机构，客户编号始终按代理商编号累计 0001、0002、0003……）。例如 SZ-JG 下王女士/陈女生/赵先生/周女士分别对应 dod/dod/Blanche/Graycity 等不同机构，但都用 `SZ-JG-0001`~`SZ-JG-0004` 累计编号 |
| **政策体系 / 等级（两层）** | 代理商先归属一个**政策体系**（如 代理商计划/合伙人计划/自定义），体系下再分若干**等级**（如 黄金/铂金/钻石/黑钻、在韩合伙人/黄金合伙人）；每个等级独立一套佣金规则，数量可自由创建 |
| **5 阶段** | 客户生命周期宏观阶段：建档 → 预约 → 到院 → 回访 → 复购 |
| **7 档状态** | 客户微观状态：新线索 / 已联系 / 已预约 / 已确认 / 已到院 / 已施术 / 已复购 |
| **月结** | 每月汇总各代理商约定期限内推广费并生成结算单的过程。结算周期与触发时间**可由用户在配置中心自定义**，**默认值为自然月**（每月 1 日 09:00 触发上月结算）。2026-07-24 修订：Q03 从"固定自然月"改为"可自定义，默认自然月" |
| **结算单** | 记录代理商某月推广费明细与合计的正式文档（Word/PDF） |
| **推广费** | 代理商推荐客户成交后，按 **成交金额 × 月度累计阶梯比例**（依 政策体系→等级→个性化覆盖 的规则）计算出的分成，精确到分 |
| **政策体系** | 代理商的归属分组（如 代理商计划、合伙人计划、自定义），是佣金规则的顶层容器 |
| **合作状态** | 代理商状态：合作中（正常）/ 暂停（不产生新订单、不参与月结）/ 已终止（停止、历史只读） |
| **规则引擎（浅深度）** | 首期仅支持配置固定参数：推广费规则 = 比例 + 月度累计成交金额阶梯区间；主动跟进规则 = 固定触发条件类型 + 适用对象范围 + 空白备注区 + 建议方向。不做复杂条件分支、表达式或 DSL |
| **to B / to C** | 统计双视角：to B = 代理商侧（推广费/月结/等级）；to C = 客户侧（消费/订单/跟进/复购） |
| **成交金额** | 客户订单的实际成交价，由人工录入，系统不对接外部系统 |
| **施术项目** | 客户在机构做的医美/医疗项目（如双眼皮、隆鼻等） |
| **主动跟进提醒** | 系统根据内置规则、可配置规则或客服自定义，在术前、到院、术后、复购、维护等节点提醒**内部员工**主动跟进的待办（非发给客户）。包含治疗前提醒、到院提醒、术后 1/7/30/90/180 天提醒、生日/节日问候、老客回访等 |
| **翻译** | 涉外客户到院时陪同翻译的人员 |
| **脱敏** | 隐藏敏感信息的部分字符（如手机号显示为 138****5678） |
| **MVP** | Minimum Viable Product，最小可行产品，即首版必须上线的功能 |
| **Non-goals** | 非目标，明确本项目不做的事情 |
| **配置版本快照** | 每次配置修改保存时，系统自动将当前配置序列化为 JSONB 存入 `config_snapshots` 表。按配置模块分类（佣金规则/状态流转/月结周期等）。管理员可查看历史快照列表、对比差异，并回滚到任意版本。回滚不影响历史已结算数据（FR-07-08） |
| **代理商类型代码** | 代理商编号中的类型标识符，2-4 位大写字母数字。系统默认 JG/GT/KR 三种，管理员可在配置中心新增自定义类型代码（如 VIP、OS），全局唯一，只停不删。v1.9 统一为 `简称-类型代码` 格式（包括 KR 从 `KR-DY` 改为 `DY-KR`）（FR-07-09） |
